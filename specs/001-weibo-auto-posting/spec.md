# Feature Specification: Weibo 부동산 자동 포스팅 시스템

**Feature Branch**: `001-weibo-auto-posting`
**Created**: 2026-02-22
**Status**: Draft
**Input**: User description: "일본 부동산 매물을 중국 Weibo에 자동 포스팅하여 중국 바이어에게 노출하는 시스템"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Telegram으로 매물 입력 및 Weibo 포스팅 (Priority: P1)

사용자가 Telegram Bot에 부동산 매물 사진과 텍스트를 전송하면,
시스템이 AI를 통해 중국어로 번역·포맷팅한 후 Weibo에 자동 게시한다.

**Why this priority**: 이것이 시스템의 핵심 가치 제안이다.
매물 정보의 입력부터 Weibo 게시까지의 end-to-end 파이프라인이
동작하지 않으면 시스템의 존재 의의가 없다.

**Independent Test**: Telegram에 매물 사진 1장 + 텍스트를 보내고,
Weibo에 중국어로 포맷팅된 게시물이 올라가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 Telegram Bot에 사진 3장과 일본어 매물 정보를 전송,
   **When** 시스템이 메시지를 수신하고 처리,
   **Then** Weibo에 중국어 번역된 매물 게시물(사진 포함)이 게시되고
   Telegram으로 게시물 링크가 전송된다.

2. **Given** 사용자가 한국어로 매물 정보를 입력,
   **When** 시스템이 메시지를 수신,
   **Then** 입력 언어가 자동 감지되어 동일하게 중국어로 번역 및 포스팅된다.

3. **Given** 사용자가 자유 형식으로 매물 정보를 입력 (구조화되지 않은 텍스트),
   **When** AI가 텍스트를 파싱,
   **Then** 부동산 매물 템플릿(매물명, 위치, 가격, 면적 등 필수 항목)에
   맞춰 자동 구조화된다.

---

### User Story 2 - 미리보기 및 승인 후 포스팅 (Priority: P2)

사용자가 번역 결과를 Telegram에서 미리 확인하고,
승인 버튼을 눌러야 Weibo에 게시되는 안전한 포스팅 플로우.

**Why this priority**: 부동산 매물 정보의 오역은 비즈니스 신뢰도에
직접적 타격을 주므로, 실수 방지를 위한 미리보기가 중요하다.
기본 모드로 설정되어야 한다.

**Independent Test**: Telegram에 매물을 보내면 번역 미리보기가 먼저
전송되고, 승인 버튼 클릭 후에만 Weibo에 게시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 시스템이 기본 미리보기 모드(`/preview`)로 설정,
   **When** 사용자가 매물 정보를 전송,
   **Then** 번역·포맷팅 결과가 Telegram 미리보기로 전송되고,
   "포스팅" 버튼과 "수정 요청" 버튼이 표시된다.

2. **Given** 미리보기가 표시된 상태,
   **When** 사용자가 "포스팅" 버튼을 클릭,
   **Then** 미리보기 내용 그대로 Weibo에 게시되고 결과 링크가 전송된다.

3. **Given** 사용자가 `/auto` 명령어를 입력,
   **When** 이후 매물 정보를 전송,
   **Then** 미리보기 없이 즉시 Weibo에 포스팅되고 결과 링크가 전송된다.

---

### User Story 3 - 해시태그 자동 생성 및 환율 환산 (Priority: P3)

매물 게시물에 관련 해시태그가 자동으로 추가되고,
일본 엔화 가격이 중국 위안화로 실시간 환산되어 표시된다.

**Why this priority**: 해시태그와 환율 환산은 중국 바이어의
검색 노출과 가격 이해도를 높이는 부가 가치 기능이다.
핵심 파이프라인 없이는 의미가 없으므로 P3이다.

**Independent Test**: 매물 포스팅에 적절한 해시태그가 포함되어 있고,
가격 항목에 엔화와 위안화가 함께 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 매물 가격이 일본 엔화로 입력,
   **When** 시스템이 포맷팅을 수행,
   **Then** 가격 항목에 엔화 원금과 실시간 환율 기반 위안화 환산액이
   함께 표시된다.

2. **Given** 매물 게시물이 생성,
   **When** 시스템이 해시태그를 추가,
   **Then** 매물 유형·위치·투자 관련 중국어 해시태그가
   자동 생성되어 게시물 하단에 포함된다(예: #日本房产 #海外投资).

---

### User Story 4 - 에러 처리 및 재시도 (Priority: P4)

포스팅 실패 시 자동 재시도하고, 최종 실패 시
사용자에게 Telegram으로 알린다.

**Why this priority**: 외부 API 의존성이 높은 시스템에서
안정성 확보를 위한 필수 기능이지만,
핵심 플로우가 먼저 동작해야 의미가 있다.

**Independent Test**: Weibo API 오류를 시뮬레이션하여
재시도가 수행되고, 최종 실패 시 Telegram 알림이 오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Weibo 포스팅이 일시적 오류로 실패,
   **When** 시스템이 재시도를 수행,
   **Then** 최대 3회까지 재시도하며, 성공 시 정상 결과를 전송한다.

2. **Given** 3회 재시도 모두 실패,
   **When** 최종 실패가 확정,
   **Then** 사용자에게 구체적인 에러 메시지와 함께 Telegram 알림이 전송되고,
   실패 이력이 로컬에 저장된다.

---

### Edge Cases

- 사용자가 사진 없이 텍스트만 전송하면 어떻게 되는가?
  → 텍스트만으로 Weibo 게시물을 생성한다(사진 없는 게시 허용).
- 사용자가 9장 초과 사진을 전송하면 어떻게 되는가?
  → 처음 9장만 사용하고, 초과분은 무시됨을 사용자에게 알린다.
- 매물 정보에서 필수 항목(가격, 위치 등)이 누락되면 어떻게 되는가?
  → 확인 가능한 항목만 포맷팅하고, 누락 항목은 빈칸 처리 후
  미리보기에서 사용자에게 보완을 요청한다.
- 환율 API가 응답하지 않으면 어떻게 되는가?
  → 마지막으로 성공한 환율을 사용하되, 게시물에 환율 기준일시를 표기한다.
- Weibo API 접근이 불가능한 경우(VPN 이슈 등)?
  → 포스팅 실패로 처리하고 사용자에게 네트워크 상태 확인을 요청한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Telegram Bot을 통해 사진(최대 9장)과 텍스트를
  동시에 수신할 수 있어야 한다.
- **FR-002**: 시스템은 입력 텍스트의 언어(일본어, 중국어, 한국어)를
  자동 감지해야 한다.
- **FR-003**: 시스템은 입력 텍스트를 简体中文으로 번역해야 하며,
  일본 부동산 전문 용어를 정확하게 처리해야 한다.
- **FR-004**: 시스템은 자유 형식 텍스트를 부동산 매물 템플릿
  (매물명, 위치, 가격, 면적, 간취리, 건축년도, 구조,
  최근역, 관리비, 수선적립금, 이율, 현황, 소유권,
  토지면적, 특징, 연락처)으로 자동 구조화해야 한다.
- **FR-005**: 시스템은 JPY 가격을 실시간 환율을 반영하여
  CNY로 환산하여 함께 표시해야 한다.
- **FR-006**: 시스템은 Weibo 개인 계정에 사진과 텍스트를
  포스팅할 수 있어야 한다.
- **FR-007**: 시스템은 매물 유형·위치·투자 관련 중국어 해시태그를
  자동 생성하여 게시물에 포함해야 한다.
- **FR-008**: 시스템은 기본적으로 미리보기 모드로 동작하며,
  사용자 승인 후 포스팅해야 한다.
- **FR-009**: 사용자가 `/auto` 명령어로 즉시 포스팅 모드를
  전환할 수 있어야 한다.
- **FR-010**: 포스팅 완료 시 Weibo 게시물 링크를 Telegram으로
  전송해야 한다.
- **FR-011**: 포스팅 실패 시 최대 3회 자동 재시도해야 한다.
- **FR-012**: 최종 실패 시 구체적 에러 메시지를 Telegram으로
  전송해야 한다.
- **FR-013**: 모든 포스팅 이력(성공/실패)을 로컬에 저장해야 한다.
- **FR-014**: Weibo 업로드 요구사항에 맞춰 이미지를 자동
  리사이즈해야 한다.

### Key Entities

- **매물(Property Listing)**: 부동산 매물 정보의 핵심 데이터 단위.
  16개 필수 항목(매물명, 위치, 가격, 면적, 간취리, 건축년도,
  구조, 최근역, 관리비, 수선적립금, 이율, 현황, 소유권,
  토지면적, 특징, 연락처)으로 구성.
- **포스팅(Post)**: Weibo에 게시된 하나의 게시물.
  매물 정보(포맷팅된 중국어 텍스트) + 사진(최대 9장) + 해시태그로 구성.
  상태(대기/승인/게시완료/실패)를 가짐.
- **포스팅 이력(Post History)**: 모든 포스팅 시도의 기록.
  타임스탬프, 성공/실패 여부, 에러 메시지, Weibo URL 포함.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 Telegram에 매물 정보를 입력한 후 5분 이내에
  Weibo 게시물이 게시된다(미리보기 승인 시간 제외).
- **SC-002**: AI 번역의 부동산 전문 용어 정확도가 90% 이상이다
  (간취리, 관리비 등 핵심 용어 기준).
- **SC-003**: 일 1~3건 포스팅 운영 시 시스템 가용률이 95% 이상이다.
- **SC-004**: 포스팅 실패 시 사용자가 1분 이내에 실패 알림을 받는다.
- **SC-005**: 입력 가능한 3개 언어(일본어, 중국어, 한국어) 모두에서
  올바른 중국어 출력이 생성된다.

## Assumptions

- Weibo Open Platform 공식 API를 사용하여 프로그래밍 방식으로
  게시한다(research.md에서 확정: 일본에서 VPN 없이 접근 가능).
- 라즈베리파이에서 Weibo 서비스에 네트워크 접근이 가능하다
  (일본에서 VPN 불필요 확인됨).
- Claude API를 anthropic 라이브러리를 통해 직접 호출한다
  (OpenClaw 연동은 별도 스펙(002)으로 분리).
- 사용자는 단일 운영자(1명)로 동시 사용을 고려하지 않는다.
- 하루 포스팅 빈도는 1~3건으로, 대량 처리 최적화는 불필요하다.
