# Feature Specification: Weibo 쿠키 자동 갱신 시스템

**Feature Branch**: `005-cookie-auto-refresh`
**Created**: 2026-02-22
**Status**: Draft
**Input**: User description: "Weibo 쿠키 자동 갱신 시스템 - 쿠키 만료 사전 알림(Telegram) + CookieCloud 브라우저 확장 연동으로 반자동 쿠키 갱신. 현재 깨진 refresh_cookies_via_openclaw() 대체."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 쿠키 만료 사전 알림 (Priority: P1) 🎯 MVP

운영자는 Weibo 쿠키가 만료되기 전에 Telegram 알림을 받아, 서비스 중단 없이 미리 대응할 수 있다. 현재 시스템은 쿠키가 이미 만료된 후에야 알림을 보내기 때문에, 포스팅이 실패한 뒤에야 문제를 인지하게 된다. 사전 알림을 통해 쿠키 만료 전에 갱신 조치를 취할 수 있다.

**Why this priority**: 쿠키 만료로 인한 포스팅 실패를 사전에 방지하는 핵심 기능. 외부 의존성 없이 즉시 구현 가능하며, 이것만으로도 운영 안정성이 크게 향상된다.

**Independent Test**: 쿠키 나이가 임계치를 초과하면 Telegram에 경고 알림이 도착하는지 확인하여 독립 테스트 가능

**Acceptance Scenarios**:

1. **Given** 쿠키가 유효하고 설정 후 36시간 이상 경과했을 때, **When** 주기적 검증이 실행되면, **Then** 운영자에게 "쿠키가 곧 만료될 수 있습니다" 경고 알림이 Telegram으로 전송된다
2. **Given** 쿠키가 유효하고 설정 후 36시간 미만일 때, **When** 주기적 검증이 실행되면, **Then** 알림 없이 정상 로그만 기록된다
3. **Given** 쿠키가 이미 만료되었을 때, **When** 주기적 검증이 실행되면, **Then** 운영자에게 "쿠키가 만료되었습니다" 긴급 알림이 갱신 방법 안내와 함께 전송된다
4. **Given** 쿠키가 설정되지 않았을 때, **When** 주기적 검증이 실행되면, **Then** 알림 없이 조용히 종료된다

---

### User Story 2 - CookieCloud 연동으로 반자동 갱신 (Priority: P2)

운영자는 브라우저에서 CookieCloud 확장 프로그램을 통해 쿠키를 자동 동기화하고, 봇이 해당 서버에서 최신 쿠키를 가져와 자동으로 갱신한다. 브라우저에서 Weibo에 로그인만 하면 별도의 /cookie 명령어 입력 없이 봇의 쿠키가 자동 갱신된다.

**Why this priority**: P1(알림)이 "문제를 알려주는" 수동 방식이라면, P2는 "문제를 자동으로 해결하는" 반자동 방식. CookieCloud 서버 설정이 필요하므로 P1보다 후순위이나, 설정 완료 후에는 운영 편의성이 대폭 향상된다.

**Independent Test**: CookieCloud 서버에 Weibo 쿠키가 동기화된 상태에서, 봇의 쿠키가 만료되면 자동으로 CookieCloud에서 가져와 갱신되는지 확인

**Acceptance Scenarios**:

1. **Given** CookieCloud 연동이 설정되어 있고 쿠키가 만료되었을 때, **When** 주기적 검증이 실행되면, **Then** 시스템이 CookieCloud 서버에서 최신 쿠키를 가져와 자동 갱신하고, 성공 알림을 Telegram으로 전송한다
2. **Given** CookieCloud 연동이 설정되어 있고 서버에 유효한 Weibo 쿠키가 없을 때, **When** 갱신을 시도하면, **Then** 갱신 실패로 처리되고 수동 갱신 안내 알림이 전송된다
3. **Given** CookieCloud 연동이 설정되지 않았을 때, **When** 쿠키가 만료되면, **Then** CookieCloud 시도를 건너뛰고 즉시 수동 갱신 안내 알림을 전송한다
4. **Given** CookieCloud 서버에 연결할 수 없을 때, **When** 갱신을 시도하면, **Then** 연결 실패를 로그에 기록하고 수동 갱신 안내 알림을 전송한다

### User Story 3 - 깨진 자동 갱신 코드 정리 (Priority: P1)

현재 존재하는 `refresh_cookies_via_openclaw()` 메서드는 실제로 존재하지 않는 외부 서비스 엔드포인트를 호출하여 항상 실패한다. 이 데드 코드를 제거하고 새로운 갱신 메커니즘으로 교체하여 코드 정합성을 확보한다.

**Why this priority**: 깨진 코드가 매 검증 주기마다 불필요한 에러 로그를 생성하고, 60초 타임아웃까지 대기하게 만든다. 이는 P1/P2 구현의 전제 조건이다.

**Independent Test**: 쿠키 만료 시 더 이상 존재하지 않는 서비스 호출을 시도하지 않고, 새로운 갱신 흐름(CookieCloud 또는 알림)으로 처리되는지 확인

**Acceptance Scenarios**:

1. **Given** 쿠키가 만료되었을 때, **When** 주기적 검증이 실행되면, **Then** 존재하지 않는 외부 서비스 호출 없이 새로운 갱신 흐름이 실행된다
2. **Given** CookieCloud가 설정되어 있을 때, **When** 쿠키 갱신이 필요하면, **Then** CookieCloud를 통한 갱신이 시도된다
3. **Given** CookieCloud가 미설정이고 쿠키가 만료되었을 때, **When** 갱신 흐름이 실행되면, **Then** 즉시 수동 갱신 알림만 전송된다 (불필요한 대기 없이)

---

### Edge Cases

- 쿠키 파일이 손상되었거나 파싱이 실패하면 → 손상된 쿠키로 취급하여 만료 알림과 동일한 흐름으로 처리
- CookieCloud 서버가 응답은 하지만 잘못된 데이터를 반환하면 → 복호화/파싱 실패로 처리하고 수동 갱신 안내
- CookieCloud에서 가져온 쿠키가 이미 만료된 상태라면 → Weibo 검증 후 무효 판정, 수동 갱신 안내
- 네트워크 일시 장애로 쿠키 검증 자체가 실패하면 → 검증 불가 상태로 기록, 다음 주기에 재시도
- 만료 임박 경고가 반복 전송되면 → 마지막 경고 시각을 기록하여 24시간 이내 중복 경고 방지

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 저장된 쿠키의 나이(설정 시점 이후 경과 시간)를 계산할 수 있어야 한다
- **FR-002**: 시스템은 쿠키 나이가 설정된 임계치(기본 36시간)를 초과하면 운영자에게 Telegram 경고 알림을 보내야 한다
- **FR-003**: 시스템은 쿠키가 만료되었을 때 갱신 방법 안내를 포함한 긴급 알림을 보내야 한다
- **FR-004**: 시스템은 선택적으로 CookieCloud 서버와 연동하여 쿠키를 자동 갱신할 수 있어야 한다
- **FR-005**: CookieCloud 연동 시, 시스템은 서버에서 암호화된 쿠키 데이터를 가져와 복호화한 후 Weibo 관련 쿠키만 추출해야 한다
- **FR-006**: CookieCloud에서 가져온 쿠키는 Weibo 서비스를 통해 유효성 검증 후에만 적용해야 한다
- **FR-007**: 시스템은 기존의 비작동 자동 갱신 코드를 제거하고 새로운 갱신 흐름으로 대체해야 한다
- **FR-008**: CookieCloud 연동 설정이 없어도 시스템의 나머지 기능(사전 알림, 수동 쿠키 설정 명령어)은 정상 동작해야 한다
- **FR-009**: 쿠키 갱신 성공/실패 여부는 Telegram 알림으로 운영자에게 보고해야 한다
- **FR-010**: CookieCloud 연동에 필요한 설정 정보(서버 주소, 인증 정보)는 환경 변수로 관리해야 한다
- **FR-011**: 만료 임박 경고는 24시간 이내에 중복 전송되지 않아야 한다

### Key Entities

- **Cookie Status**: 쿠키의 현재 상태(유효/만료/만료임박/검증불가)와 메타데이터(설정 시각, 검증 시각, 나이)
- **CookieCloud Config**: CookieCloud 연동에 필요한 설정(서버 URL, 동기화 식별자, 복호화 비밀번호). 세 값 모두 설정된 경우에만 활성화
- **Alert Record**: 운영자에게 전송된 알림 이력(유형: 경고/긴급/성공, 발송 시각). 중복 알림 방지에 사용

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 쿠키 만료 전 최소 12시간 이내에 운영자가 경고 알림을 수신하여 사전 대응할 수 있다
- **SC-002**: CookieCloud 연동 설정 완료 시, 쿠키 만료 후 다음 검증 주기(최대 6시간) 이내에 자동 갱신이 시도된다
- **SC-003**: 기존 비작동 코드 제거로, 쿠키 만료 시 불필요한 60초 대기가 제거된다
- **SC-004**: CookieCloud 미설정 시에도 알림 기능이 정상 동작하여, 운영자가 수동 갱신 안내를 받을 수 있다
- **SC-005**: 쿠키 관련 모든 상태 변화(만료 임박, 만료, 갱신 성공, 갱신 실패)가 Telegram 알림으로 운영자에게 전달된다

## Assumptions

- Weibo 쿠키 수명은 1~3일이며, 36시간을 만료 임박 임계치의 합리적인 기본값으로 설정한다
- CookieCloud 브라우저 확장 프로그램과 서버는 운영자가 별도로 설치/설정한다 (본 기능은 클라이언트 연동만 담당)
- 기존 수동 쿠키 설정 Telegram 명령어는 항상 사용 가능한 백업 수단으로 유지한다
- CookieCloud의 쿠키 데이터는 암호화되어 전송되며, 복호화에 비밀번호와 식별자가 필요하다
- 주기적 검증 간격(6시간)은 기존 설정을 유지한다
